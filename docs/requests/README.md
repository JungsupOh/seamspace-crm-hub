# 개발팀(mDiary 백엔드) 요청 문서

CRM에서 mDiary 백엔드에 요청하는 API·연동 건을 모아둡니다.
그대로 복사해 전달할 수 있도록 요청 하나당 문서 하나로 작성합니다.

## 목록

| 문서 | 요청일 | 상태 | 요약 |
|---|---|---|---|
| [쿠폰 무효화 API](./coupon-revoke-api.md) | 2026-07-20 | 요청 준비 | 계약 결렬·오발급 쿠폰을 정지시키는 `coupon_revoke` |

관련 문서: [쿠폰 상태 변경 Webhook 명세](../COUPON_WEBHOOK_SPEC.md)

## 상태 표기

- **요청 준비** — 문서 작성 완료, 아직 전달 전
- **요청 전달** — 개발팀에 전달, 회신 대기
- **개발 중** — 착수 확인됨
- **완료** — 배포 확인 및 CRM 연동 완료

## 작성 규칙

요청서는 **받는 쪽이 되묻지 않아도 되도록** 씁니다.

1. **목적을 업무 상황으로 설명한다** — "무효화가 필요하다"가 아니라
   "계약이 결렬되어 전달한 쿠폰을 회수해야 한다"
2. **선택지를 남기지 않는다** — "이래도 되고 저래도 된다"는 구현자에게
   판단을 떠넘기는 것이고, 결국 예상과 다르게 구현된다
3. **상황별로 응답을 하나씩 못 박는다** — HTTP 코드와 응답 본문까지
4. **기존 데이터 표현을 먼저 확인하고 그에 맞춘다** — 새 컬럼을 요구하기 전에
   현재 스키마로 표현 가능한지 본다
5. **재시도 안전성을 명시한다** — 네트워크 오류 시 같은 요청이 반복될 수 있다
6. **CRM 쪽 연동 계획을 함께 적는다** — 상대가 영향 범위를 가늠할 수 있게
